# Quick Start: установка готового приложения (ПК и телефон, без зависимостей)

Ничего собирать не нужно: ни Node, ни npm, ни git, ни компиляторов. Нужны только готовые файлы
и браузер.

Два факта, из которых всё следует:

- StackEdit — это **PWA** (веб-приложение). «Установить» его = поставить сайт как приложение силами
  браузера: отдельное окно, значок в меню, работа офлайн. Магазин приложений не участвует.
- Установка и офлайн включаются только на **защищённом контексте**: `https://…` либо `http://localhost`
  / `http://127.0.0.1`. Обычный `http://192.168.x.x` — нет (см. [phone.md](phone.md)).
- **Локальный сервер вообще не обязателен**: достаточно любого `https://`-адреса со сборкой. Ниже —
  вариант 0 (готовый адрес) и вариант со своим хостингом.

## Вариант 0: без локального сервера и без сборки

Готовая сборка опубликована и уже проверена (GitHub Pages, HTTPS, публичный доступ):

**<https://dnikulshin.ru/stackedit/>**

- **ПК:** откройте адрес в Chrome → значок «Установить» в адресной строке или ⋮ → «Сохранить и
  поделиться» → «Установить приложение».
- **Телефон (Android):** тот же адрес в Chrome → ⋮ → «Установить приложение».
- **Телефон (iOS):** Safari → «Поделиться» → «На экран „Домой“».

Проверено на этом адресе: Chrome ошибок установки не видит, Service Worker активируется и управляет
страницей, офлайн-перезагрузка работает.

> Это демо-деплой из ветки `gh-pages` этого репозитория (`.nojekyll`, сборка под `base=/stackedit/`).
> Свой такой же адрес делается за пару минут — см. «Свой HTTPS-адрес» ниже.

### Свой HTTPS-адрес бесплатно

**GitHub Pages (подкаталог `<user>.github.io/<repo>/`):**

```bash
./scripts/build-local.sh --base /stackedit/            # base = /<имя-репозитория>/
./scripts/prepare-static.sh dist-pages --base /stackedit/
./scripts/check-static.sh dist-pages --base /stackedit/
node scripts/check-installability.mjs dist-pages --base /stackedit/
./scripts/deploy-pages.sh dist-pages                   # push в ветку gh-pages
gh api -X POST repos/<user>/<repo>/pages -f 'source[branch]=gh-pages' -f 'source[path]=/'
```

**Netlify Drop / Cloudflare Pages / свой домен (корень сайта, без `--base`):** перетащите содержимое
`dist-static` (вариант A ниже) в браузере — адрес получите сразу, HTTPS включён.

### Чего сделать нельзя

Открыть `index.html` двойным кликом (`file://`) и «установить» оттуда — браузер это запрещает:
Chrome на такой странице сообщает `not-from-secure-origin` и `no-manifest`. Service Worker по
`file://` не регистрируется вообще. Нужен `https://` или `localhost`.

### Осторожно с хостингами, закрытыми авторизацией

Если сайт отдаётся за Basic Auth / Authelia / любым логином, Service Worker не установится: запросы
из precache-списка уходят на страницу входа (`302`), Chrome помечает их `ERR_BLOCKED_BY_ORB`, и
`cache.addAll` падает. Признак: в консоли воркера — редиректы на `auth.<домен>` и `net-failed`.
Проверка: `node scripts/check-installability.mjs <адрес>` не должен показывать ошибок, а
`./scripts/check-static.sh` — 200 на всех URL из `sw.js`.

## Вариант A. Свой локальный сервер (файлы из релиза)

Файлы нужны, если хочется запускать на своём компьютере или раздавать со своего хостинга.

**A. Архив из релиза** (~9 МБ) — два формата, берите свой:

```bash
# Linux / macOS: tar.gz, разворачивается в каталог stackedit-pwa/
curl -fL -o stackedit-pwa.tar.gz \
  https://github.com/DNikulshin/stackedit/releases/latest/download/stackedit-pwa-5.15.4.tar.gz
tar xzf stackedit-pwa.tar.gz

# Windows: zip, файлы лежат прямо в корне архива (без лишней вложенной папки)
# https://github.com/DNikulshin/stackedit/releases/latest/download/stackedit-pwa-5.15.4.zip
```

> Windows: распакуйте zip («Извлечь всё») и запускайте `start-windows.cmd` из получившейся папки.
> Там же лежат `app\`, `sw.js`, `manifest….json` — это и есть корень раздачи. Если инструмент
> распаковки создал лишний уровень вложенности (`…\stackedit-pwa-5.15.4\stackedit-pwa\`), скрипт
> найдёт правильную папку сам — вручную ничего перекладывать не нужно.

**B. Docker** — файлы вообще не нужны, образ уже собран в CI:

```bash
docker run -d --name stackedit -p 8080:8080 ghcr.io/dnikulshin/stackedit:latest
# → http://localhost:8080/app
```

Образ публичный (`ghcr.io/dnikulshin/stackedit`, ~147 МБ в сжатом виде, внутри Node 14 и готовая
сборка). Проверено: `docker pull` — 21 с, `/app`, `/conf`, `/sw.js` отвечают 200.

## Шаг 2. ПК

| Способ | Что нужно | Адрес для открытия |
| --- | --- | --- |
| Docker (вариант B) | Docker | <http://localhost:8080/app> |
| Python (вариант A) | Python 3 (есть в Linux/macOS, в Windows — с python.org или из Store) | <http://localhost:8080/app/> |
| Готовые скрипты запуска | `start-windows.cmd` / `start.sh` в архиве | <http://localhost:8080/> |

Вариант B — если запускали `docker run`, дальше сразу к установке.

Вариант A — Windows: двойной клик по **`start-windows.cmd`** в папке `stackedit-pwa`
(нужен Python 3 с python.org, галочка «Add python.exe to PATH»). Скрипт сам поднимает сервер
и открывает браузер. Linux/macOS — `./start.sh` из той же папки.

Вручную то же самое:

```bash
cd stackedit-pwa
python3 -m http.server 8080        # Windows: py -m http.server 8080
```

Откройте <http://localhost:8080/> (адрес `/app/` — то же приложение; он же `start_url` манифеста).
Мгновенная проверка, что раздача верная:

```bash
curl -s http://localhost:8080/conf          # → {"allowSponsorship":false}
```

> ⚠️ **Три способа сломать запуск** (все дают «Файл манифеста отсутствует или недоступен для чтения»):
>
> 1. Открыть `app\index.html` двойным кликом — по `file://` манифест и Service Worker не читаются.
> 2. Сделать корнем раздачи папку `app` — манифест и `/sw.js` лежат уровнем выше, будет 404.
> 3. Запустить сервер в папке **на уровень выше** — например в `…\stackedit-pwa-5.15.4`, когда файлы
>    лежат в `…\stackedit-pwa-5.15.4\stackedit-pwa`. Тогда `/` покажет список файлов, а манифест
>    будет 404.
>
> Корень раздачи — папка, где лежат `sw.js`, `manifest….json` и `app\`. Проверка: адрес
> `http://localhost:8080/manifest.c9128ce574e7548a3b0d3bcd8bfa212c.json` должен отдать JSON.
> Подробнее — [faq.md](faq.md#файл-манифеста-отсутствует-или-недоступен-для-чтения).

### Установка как приложение

> ⚠️ **Не через `chrome://extensions`.** StackEdit — PWA, а не расширение Chrome. Если загрузить наш
> каталог как «распакованное расширение», Chrome ответит «Файл манифеста отсутствует или недоступен
> для чтения» — это ошибка страницы расширений, к установке приложения отношения не имеет
> ([разбор](faq.md#файл-манифеста-отсутствует-или-недоступен-для-чтения)).

- **Chrome / Chromium / Яндекс Браузер**: значок «Установить» в адресной строке (монитор со стрелкой)
  или меню ⋮ → «Сохранить и поделиться» → «Установить приложение».
- **Edge**: «…» → «Приложения» → «Установить этот сайт как приложение».
- **Firefox**: установки PWA нет — только вкладка.

После установки появится отдельное окно без адресной строки и значок в меню приложений. Работает
офлайн: отключите сеть и запустите приложение с ярлыка.

## Шаг 3. Телефон (магазин не нужен)

Телефону нужен адрес по HTTPS. Варианты, от простого к основательному:

| Вариант | Что нужно | Установка PWA |
| --- | --- | --- |
| **Netlify Drop** — перетащить папку `stackedit-pwa` в браузере на <https://app.netlify.com/drop> | только браузер на ПК | ✅ на `https://<имя>.netlify.app` |
| **Cloudflare Pages / GitHub Pages** из той же папки | браузер + аккаунт | ✅ |
| **Своя машина с HTTPS** (VPS/Caddy, туннель) | сервер | ✅ см. [self-host.md](self-host.md) |
| **Локальная сеть**: `python3 -m http.server 8080` на ПК → `http://192.168.x.x:8080/app/` | ПК + Wi‑Fi | ❌ нет HTTPS: работает как сайт, без установки и офлайна |
| **Docker на ПК** → тот же адрес по локалке | Docker | ❌ аналогично |

После публикации папки:

1. откройте адрес в **Chrome** на Android → меню ⋮ → **«Установить приложение»**;
2. на iOS — только **Safari**: «Поделиться» → **«На экран „Домой“»**;
3. готово: значок на домашнем экране, приложение открывается в отдельном окне и работает без сети.

Что важно при загрузке папки на хостинг: перетаскивайте/загружайте **содержимое** папки
`stackedit-pwa` так, чтобы `index.html`, `app/`, `conf`, `sw.js` оказались в корне сайта.

### Проверка, что хостинг подходит

Откройте (или `curl`) на своём адресе — все четыре URL должны отдавать 200:

| URL | Зачем |
| --- | --- |
| `/app/` | само приложение (и `start_url` манифеста) |
| `/conf` | публичные ключи провайдеров (в самостоятельной сборке — `{"allowSponsorship":false}`) |
| `/oauth2/callback` | его запрашивает Service Worker при установке |
| `/sw.js` | Service Worker (офлайн и установка) |

Если `/app/` или `/oauth2/callback` отдают 404 — Service Worker не установится: установка PWA
и офлайн не заработают.

Если 404 дают `/manifest...json` и `/sw.js` — корень раздачи выбран неверно (взята папка `app`
вместо `stackedit-pwa`); именно в этом случае Chrome пишет «Файл манифеста отсутствует или
недоступен для чтения».

## Проверено и не проверено

Проверено на этой сборке:

- статический каталог `stackedit-pwa` (в архиве — то же самое) раздаётся `python3 -m http.server`:
  `/app/` открывается, Service Worker активен и управляет страницей, **офлайн-перезагрузка работает**,
  ошибок в консоли нет;
- автоматическая проверка `./scripts/check-static.sh` — все URL из precache Service Worker возвращают
  200 (эта же проверка гоняется в CI при каждом пуше);
- образ из GHCR: `docker pull` без авторизации, контейнер `healthy`, `/app`, `/conf`, `/sw.js` — 200;
- на ПК установка PWA из Chrome с `http://localhost:8080/app` (манифест, SW, `beforeinstallprompt`);
- `start.sh` из архива поднимает сервер и даёт те же 200 на `/app/`, `/conf`, `/sw.js`, `/manifest...json`.
  `start-windows.cmd` собран по тому же принципу, но на Windows не запускался (в среде сборки нет Windows).

Не проверялось (нет возможности в этой среде): конкретные хостинги Netlify Drop / Cloudflare Pages /
GitHub Pages, Termux на Android, установка с реального домена по HTTPS — поведение обычной статики
проверено локально, сами сервисы могут добавлять свои особенности.
